# 五项任务算法效果及格值与18分换算（试运行暂定）

每项任务仍为25分：**算法效果18分＋正确性4分＋鲁棒性2分＋效率1分**。本文只调整算法效果18分的换算，**不把整个25分都按质量指标计算**。前版文档对此理解错误，本版予以更正。

## 各项跑出什么值、多少算效果及格

服务器沿用各算法原有的综合质量指标Q，下面为各自的暂定及格值T：

| 任务 | 实际评测指标Q | 及格值T | 达到T的算法效果分 |
| --- | --- | ---: | ---: |
| LR 逻辑回归 | (准确率 + 宏平均F1) / 2 | **0.75** | **10.8 / 18** |
| SVM 支持向量机 | (准确率 + 宏平均F1) / 2 | **0.75** | **10.8 / 18** |
| GBDT 回归 | 0.6/(1+NRMSE) + 0.4/(1+NMAE) | **0.60** | **10.8 / 18** |
| KMeans 聚类 | 0.6×ARI + 0.4×NMI | **0.50** | **10.8 / 18** |
| HMM 序列预测 | 0.8×状态准确率 + 0.2×整序列准确率 | **0.60** | **10.8 / 18** |

表中的及格值针对完整Q，不是单独一个准确率、ARI、RMSE或状态准确率。例如LR准确率75%时，仍需结合宏平均F1判定。GBDT原误差越小越好，已经通过Q公式转换成越高越好；归一化尺度沿用训练集统计。

## 18分如何换算

先令q为Q截断到[0,1]后的值；KMeans负Q对应0效果分，原Q保留。按该任务的T计算：

- q ≤ T：效果分 = 10.8 × q / T。
- q > T：效果分 = 10.8 + 7.2 × (q − T) / (1 − T)。

因此，Q=0对应0分，Q=T对应及格效果分10.8分，Q=1对应18分。超过及格值越多，效果分越高；不会一过线就直接满分。

例如LR/SVM的T=0.75：

| 实测Q | 效果分（满分18） |
| ---: | ---: |
| 0.50 | 7.20 |
| 0.75 | 10.80 |
| 0.80 | 12.24 |
| 0.90 | 15.12 |
| 1.00 | 18.00 |

政策版本：`trial-quality18-anchors-20261018-v1`。其余正确性、鲁棒性、效率7分保留各自真实测量规则，不挪入效果分、不默认赠送。已得到的效果分可先展示；尚未测得的分项标为未就绪，总分待所需分项齐全后求和。合法选择四项或五项，最高四项合计满分100的规则保持。

## 说明与查分

这些阈值是暂定教学标准，不是五项实测拟合结果。单次评测按1 CPU、1 GiB内存设计，编译60秒、预测执行30秒、所选任务内部总限时300秒；限额以目标实际生效配置为准。硬件决定资源预算，不能直接推算算法准确率及格线。

效果分不再等待随机baseline或班级统计；未测CPU效率不能补造成绩。真实输出、各分项与政策版本应通过原持久结果保存和回读，同一提交不能因刷新或重启漂分。服务器故障、未运行与学生程序失败须分别报告。
